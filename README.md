# RecSys Challenge 2025/26 — Group 42

End-to-end recommender pipeline for the course Kaggle leaderboard. Predicts top-10 items per user using an ensemble of **BPR-MF** (collaborative), **GRU4Rec** (sequential), and **item popularity** (global prior).

## Results on held-out validation (leave-one-out, Recall@10)

| Model | Recall@10 |
|---|---|
| Popularity baseline | 0.0174 |
| BPR-MF (20 ep, dim=64) | 0.0358 |
| GRU4Rec (20 ep, hidden=64, max_seq=50) | 0.0324 |
| **Ensemble (BPR + GRU, equal weights)** | **0.0404** |
| Ensemble (BPR=1, GRU=2, POP=0.5) | 0.0406 |

Ensemble lift over BPR alone: **+13%**. Adding popularity at equal weight *hurts* — the BPR/GRU signals are strong enough that the popularity prior pulls predictions back toward the global average. Best with popularity excluded (or down-weighted to ≤0.5).

## Reproduction

```bash
# 1. Build processed train/val split + copy test
python main.py preprocess

# 2. Train BPR + GRU on the split, sweep ensemble weights on val
python main.py eval

# 3. Retrain on train+val, write data/submission.csv for the 2,255 leaderboard users
python main.py infer
```

Or all three: `python main.py all`.

## Method

**Preprocessing.** Drop duplicate `(user_id, item_id)` pairs (keep latest by timestamp). Leave-one-out: each user's last interaction → validation, the rest → training.

**BPR-MF.** User + item embeddings (dim=64) and per-item bias. Trained with the BPR pairwise loss
`−log σ(score(u, pos) − score(u, neg))` on minibatches of `(user, pos_item, neg_item)` triples; negatives are uniform random with rejection on the user's positive set. Adam, lr=1e-3, weight_decay=1e-5, 20 epochs for the val run / 30 for inference.

**GRU4Rec.** Single-layer GRU (hidden=64) over per-user item sequences sorted by timestamp. Each sequence is capped to its most-recent 50 items — this biases the 20-year span toward recent behavior without a hard date cutoff. Output logits are computed against the tied item-embedding table; cross-entropy next-item loss with `ignore_index=0` for padding.

**Ensemble.** Each component exposes `batch_score_users(user_ids) → (B, n_items+1)`. Scores are per-row min-max normalized to [0, 1] and combined with a fixed weight vector. Mask out (a) padding index 0 and (b) items the user has seen in the training data. Top-10 per row via `torch.topk`.

**Inference.** Concatenate `processed/train.csv + processed/val.csv` (= original deduped train), retrain BPR + GRU on the full data, then predict the 2,255 sample-submission users in chunks of 1,024.

## Performance notes

- The ensemble weight sweep is a chunked batched pass (~16s for 11 weight combos on 23k val users) — per-chunk score matrices are reused across all weight combos so the work is dominated by 1 BPR matmul + 1 GRU forward per chunk.
- BPR training: ~7 min for 30 epochs (CPU). GRU training: ~37 min for 20 epochs on full train+val. Both are CPU-bound and Adam-bound.

## Cold start

- Users not in train: BPR returns the item-bias-only ranking (≈ popularity); GRU returns the cold prior from running the GRU on a single padding token.
- The submission set has **0 cold users** when training on train+val combined, so this only matters for val and is documented in [src/bpr.py](src/bpr.py) / [src/gru4rec.py](src/gru4rec.py).
